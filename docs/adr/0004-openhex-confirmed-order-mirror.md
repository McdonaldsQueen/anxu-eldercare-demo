# ADR 0004：镜像 OpenHex 已确认的外部工单

- 状态：已接受
- 日期：2026-09-19
- 取代范围：ADR 0001 中“OpenHex 不直接创建或修改浏览器内 Case”的绝对限制

## 决策

OpenHex 原始消息仍不得进入本地 Mock 决策引擎。只有已完成的 Agent 回复明确表示建单成功，并包含符合 `CASE-YYYYMMDD-NNN` 的外部工单号时，前端才可将结果镜像为 `caseSource: 'OPENHEX'` 的本地 Case。

`openhexCaseBridge` 负责确认回执和提取历史工具参数，`demoStore.importOpenhexCase` 以外部工单号执行幂等创建或补全。信息不足时进入待人工评估，不根据老人原始需求自行推断建单成功。

## 原因

真实 Agent 已能调用外部建单能力。完全忽略成功回执会让老人端、家属端和工作人员端无法展示已经存在的工单；直接把所有对话交给本地决策引擎又会混淆真实结果与 Mock 推断。受控镜像只接受明确、可追踪且带外部编号的结果，能够兼顾演示联动和边界安全。

## 后果

- Case 只持久化在当前浏览器，不是跨设备业务数据库。
- 后续接单和状态迁移仍使用本地 store action 与 `caseStateMachine`，不会回写 OpenHex 或飞书。
- 同一工单号不会重复创建；已存在的非 OpenHex Case 不会被覆盖。
- 仅出现工单号、失败回执或不确定文本时不建卡，并提示人工核对。
- 若未来增加共享 Case 后端、权限或审计，需要新的迁移 ADR，不能直接复用当前浏览器镜像。
