# 产品能力

## 产品定位

安序智护 Demo 展示从老人自然语言需求开始，到家属知情、服务人员处理和 Case 完结的多角色养老服务体验。真实 Agent 对话和业务 Case 是两套明确隔离的数据链路。

## 能力矩阵

| 角色 | 能力 | 数据来源 |
| --- | --- | --- |
| 老人 | 与安序智护进行多轮流式对话、语音转文字、刷新恢复会话 | 真实 OpenHex Agent |
| 老人 | 陪诊需求、紧急风险、风险追问、Case 进度 | 本地 Mock |
| 家属 | 查看老人状态、服务进展和安全风险 | 本地 Mock |
| 家属 | 提交联系确认、物品转交、待评估需求 | 本地 Mock |
| 服务人员 | 接单、开始、完成普通服务 | 本地 Mock |
| 服务人员 | 人工审核 Safety Case、确认风险、介入和完成 | 本地 Mock |
| 服务人员 | 接受或拒绝待评估需求 | 本地 Mock |

## 主要旅程

### 真实 Agent 对话

1. 老人输入文字或通过浏览器语音识别填入草稿。
2. 浏览器向同源令牌接口获取短时访客令牌。
3. OpenHex SDK 发送消息并通过 SSE 接收回复。
4. 会话 ID 由 SDK 持久化，刷新后加载同一访客的历史。
5. 此流程不创建任何本地 Case。

### 陪诊 Mock Case

1. 演示工具栏触发两轮本地消息，收集医院和时间。
2. 决策引擎创建普通服务 Case。
3. 服务人员接单、开始服务、完成服务。
4. 老人与家属看到同一 Case 的状态和时间线。

### Safety Mock Case

1. 演示工具栏或 Phase 4 本地对话命中风险信号。
2. 系统建立 `WAITING_FOR_REVIEW` Safety Case，并显示补充问题。
3. 工作人员人工确认最终风险类型和等级。
4. 工作人员介入并完成处理，家属同步看到进展。

## 演示工具栏

工具栏是技术和 Mock 能力的唯一集中入口。切换到 Phase 4 或触发快捷 Case 时，只操作本地 store；OpenHex 模式默认只展示真实 Agent 对话。诊断信息不包含消息正文、令牌或密钥。
